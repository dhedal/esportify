Documentation Technique - TP Développeur Web et Web Mobile

1. Introduction

Cette documentation technique décrit la conception et l’architecture du projet, en détaillant les technologies utilisées et les choix de développement.

2. Architecture et technologies utilisées

Le projet repose sur une architecture MVC en utilisant :

  • Spring Boot : Framework backend facilitant le développement et la gestion des API REST.
  • Spring Security : Gestion de l’authentification et des autorisations des utilisateurs.
  • Spring Data JPA : Interaction simplifiée avec la base de données MySQL.
  • Thymeleaf : Moteur de template pour la gestion du rendu côté serveur.
  • Bootstrap CSS : Framework utilisé pour la mise en page et la responsivité de l’interface utilisateur.
  • JavaScript (AJAX) : Gestion des requêtes asynchrones pour améliorer l’expérience utilisateur.

3. Configuration de l’environnement

L’environnement de développement est configuré avec :

  • IDE : IntelliJ IDEA.
  • Base de données : MySQL, gérée via MySQL Workbench.
  • Gestion de version : GitHub, avec un workflow basé sur Git Flow.
  • Serveur d’application : Spring Boot intégré avec Tomcat.

4. Modèle Conceptuel de Données (MCD)

Le Modèle Conceptuel de Données (MCD) ci-dessous illustre la structure des entités et leurs relations dans l’application Esportify.

4.1 Description des entités

  • user : Stocke les informations des utilisateurs (email, mot de passe, pseudo, statut).
  • event : Contient les événements organisés (titre, description, dates, statut, organisateur).
  • event_participant : Permet de gérer les utilisateurs inscrits aux événements.
  • ask : Gère les demandes spécifiques des utilisateurs (ex. demande pour devenir organisateur).
  • event_image : Stocke les images associées à chaque événement.

4.2 Relations entre les entités

  • Un utilisateur (user) peut organiser plusieurs événements (event).
  • Un utilisateur (user) peut s'inscrire à plusieurs événements via la table event_participant.
  • Un événement (event) peut avoir plusieurs images via la table event_image.
  • Un utilisateur (user) peut soumettre des demandes via la table ask.

6. Déploiement de l’application

L’application est déployée avec Docker en orchestrant les services Spring Boot et MySQL.

6.1 Configuration des conteneurs

Le déploiement repose sur deux services :

  • Un conteneur MySQL pour gérer la base de données.
  • Un conteneur Spring Boot contenant l’application.

6.2 Étapes de déploiement

Les étapes pour exécuter l'application avec Docker :

  • Créer un fichier Dockerfile et y inclure l’image OpenJDK 21.
  • Créer un fichier docker-compose.yml pour orchestrer la base de données et l’application.
  • Construire et exécuter les conteneurs avec docker-compose up --build -d.
  • Vérifier que l’application fonctionne sur http://localhost:8080.
  • Utiliser docker-compose logs -f app pour consulter les logs.

6.3 Mise à jour et maintenance

Pour déployer une nouvelle version de l’application :

  • Construire une nouvelle version du projet avec mvn clean package.
  • Relancer le déploiement avec docker-compose up --build -d.
